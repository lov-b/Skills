# 八股知识库格式

在新增、合并、修订、迁移八股条目或维护索引时读取本文件。

## 推荐目录

```text
<knowledge-root>/
├── README.md
├── java/
│   ├── Java基础.md
│   ├── 集合.md
│   ├── 并发.md
│   └── JVM.md
├── framework/
│   └── Spring.md
├── database/
│   ├── MySQL.md
│   └── Redis.md
├── middleware/
├── computer-science/
├── distributed-system/
├── system-design/
└── engineering/
```

目录按实际内容创建，不生成空目录。已有知识库结构清晰时沿用现状，不为套模板强制迁移。

## 根索引格式

```markdown
# 八股知识库

> 最近整理：YYYY-MM-DD

| 领域 | 专题 | 题目数 | 最近更新 | 文件 |
|------|------|--------|----------|------|
| Java | 集合 | 12 | YYYY-MM-DD | [集合](java/集合.md) |
```

题目数按稳定 ID 统计，包含主问题和嵌套子问题；更新时间必须与专题文件一致。没有根索引时创建；已有等价索引时沿用，不重复建立。

## 问题层级与递进关系

标题层级表达栏目和问题之间的语义关系，不按答案长短决定。网站模式先保留原文标题树；原网页若仅为展示而使用不规范字号，再按语义关系纠正：

| 层级 | 用途 |
|------|------|
| `#` | 专题文件标题 |
| `##` | 原文一级栏目，或没有栏目包裹的独立主问题/父问题 |
| `###` | 栏目下的主问题；也可用于 `##` 问题内部的简答、原理展开、递进追问、易错点与来源 |
| `####` | `###` 问题的子问题，或位于“递进追问”中的子问题 |

判断规则：

- 网站模式必须先提取页面标题树和原始顺序；用 `> 原文结构：[页面标题](URL)` 标识该组内容所依据的页面。
- 网页的栏目标题即使不是问句也应保留，用来承载其下的问题；不得只保留问题标题并全部提升为 `##`。
- 原文标题字号与语义冲突时，以栏目、父问题、子问题的实际依赖关系为准，但不打乱页面内原始顺序。
- 问题需要依赖前一个问题的对象、结论或场景才能理解时，它是子问题，不得与父问题同级。
- “为什么”“如何实现”“如果条件变化会怎样”“还有哪些边界”等沿同一对象继续深挖的内容，通常属于递进追问。
- 两个问题能够各自脱离上下文完整提问，且不存在前置依赖时，才视为并列主问题。
- 保留来源或对话中的逻辑顺序；可以补全指代，但不得为了关键词排序打乱“概念 → 原理 → 实现 → 场景 → 边界”等递进链。
- 更深层追问放在最近的 `####` 子问题下，用有序列表或加粗问句表示，不继续提升为 `##`，也不产生标题越级。
- 主问题和子问题都使用稳定 ID。迁移层级时保留原 ID，并同步修复索引和内部链接。
- 问题标题已经位于 `###` 或更深层时，答案内部的“简答”“原理展开”“来源”等改用加粗标签，避免与问题标题同级或造成标题越级。

## 专题文件格式

```markdown
# {专题名称}

> 说明：{覆盖范围}
> 最近更新：YYYY-MM-DD

---

> 原文结构：[{页面标题}]({URL})

## {原文栏目标题；页面没有栏目时可直接使用父问题}

### {栏目下的真实问题}

<a id="{stable-id}"></a>

**简答**

{直接答案。}

**来源**

- [{资料标题}]({URL})

---

## {真实、可直接提问的问题标题}

<a id="{stable-id}"></a>

> ID：`{stable-id}`
> 标签：`{tag-1}`、`{tag-2}`
> 难度：基础 | 进阶 | 场景
> 最近校验：YYYY-MM-DD
> 适用范围：{JDK/框架/协议版本或“通用”}

### 简答

{先直接回答问题，内容适合 30～90 秒口述。}

### 原理展开

{解释必要术语、机制、执行链和因果关系。按内容选择段落、列表、表格或代码。}

### 递进追问

#### {依赖当前父问题的子问题}

<a id="{child-stable-id}"></a>

**简答：** {直接回答子问题，并补足必要主语。}

**原理与边界：** {按需解释机制、前提、版本差异或场景。}

**来源：**

- [{资料标题}]({URL})

### 易错点与边界

- {容易混淆的概念、例外、版本差异或实际工程边界}

### 来源

- [{资料标题}]({URL})
- 对话来源：{当前对话或可定位的任务标题/日期；没有稳定链接时不伪造链接}

---
```

简单主问题可以省略“原理展开”或“递进追问”，但不得省略直接答案和来源。没有可靠外部来源时，明确写“待外部校验”，不能伪造引用。

来源条目只保留资料标题和可直接访问的文章 URL，不追加来源类型、访问日期、固定 commit、源码快照或原文快照链接。

不在每个问题正文中维护修订记录。修订时直接更新答案，“最近校验”反映当前内容的最后校验日期；纠错或版本调整的依据归入“来源”或“易错点与边界”，历史变更由 Git 追踪。

## 稳定 ID

格式建议：

```text
{domain}-{topic}-{question-slug}
```

示例：

- `java-collection-hashmap-thread-safety`
- `java-jvm-class-loading-parent-delegation`
- `database-mysql-leftmost-prefix`

规则：

- 使用小写英文、数字和连字符
- 同一问题合并或迁移时保留 ID
- 问法调整不应随意更换 ID
- 拆成两个独立问题时保留主问题 ID，并为新问题创建新 ID

## 归一化与去重

比较顺序：

1. 问题意图是否相同
2. 核心对象和机制是否相同
3. 适用版本和场景是否相同
4. 已有答案是否覆盖本次新增信息
5. 来源可靠性是否更高或更新

仅关键词重合不能证明重复；标题不同也不能证明是新题。

常见处理：

- 同义问法：保留一个主标题，其他问法写入标题下的别名说明或索引关键词
- 父子问题：主问题使用 `##`，子问题默认作为父问题“递进追问”中的 `####`；不得仅因子问题高频就提升为同级，只有确认不存在语义依赖且属于并列问题时才拆为 `##`
- 版本差异：同一条目分版本说明，不重复创建近似标题
- 错误旧答案：更新正文，将纠错依据写入来源或易错点与边界，历史交由 Git 追踪
- 来源新增但内容无新增：只在来源能提升可信度时补充，否则跳过
- 大专题失控：按稳定知识域拆文件，同时修复根索引和内部链接

## 覆盖矩阵

```markdown
| 候选问题 | 问题关系/父问题 | 来源 | 已有匹配 | 决策 | 目标文件/层级/ID | 理由 |
|----------|-----------------|------|----------|------|--------------------|------|
| ... | 子问题 / java-... | JavaGuide | java-... | 合并 | java/集合.md / `####` / java-... | 补充 JDK 8 实现边界 |
```

每个候选必须有处理结果，不得只展示最终新增项。

## 质量检查

- [ ] 标题像真实面试问题，而不是宽泛名词
- [ ] 同级标题只承载并列问题，父问题和子问题没有被平铺为同级
- [ ] 子问题位于正确父问题的“递进追问”下，原始逻辑顺序得到保留
- [ ] 没有孤立子问题、标题越级或无意义的层级加深
- [ ] 简答先给结论，能够直接口述
- [ ] 原理解释没有跳过关键主语、前提和因果
- [ ] 事实、经验和推断已区分
- [ ] 版本敏感内容注明适用范围
- [ ] 至少有一个可追溯来源，或明确标记待校验
- [ ] 来源条目只包含资料标题和 URL，没有附加来源类型
- [ ] 没有固定 commit、源码快照或原文快照链接
- [ ] 没有与已有条目重复
- [ ] 稳定 ID、索引、内部链接有效
- [ ] 修订没有无意删除仍有效的内容
- [ ] 没有大段复制网站原文
