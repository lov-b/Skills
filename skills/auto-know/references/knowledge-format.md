# 八股知识库格式

在新增、合并、修订、迁移八股条目或维护索引时读取本文件。

## 推荐目录

```text
<knowledge-root>/
├── README.md
├── java/
│   ├── Java基础.md
│   ├── 集合.md
│   ├── 并发.md
│   └── JVM.md
├── framework/
│   └── Spring.md
├── database/
│   ├── MySQL.md
│   └── Redis.md
├── middleware/
├── computer-science/
├── distributed-system/
├── system-design/
└── engineering/
```

目录按实际内容创建，不生成空目录。已有知识库结构清晰时沿用现状，不为套模板强制迁移。

## 根索引格式

```markdown
# 八股知识库

> 最近整理：YYYY-MM-DD

| 领域 | 专题 | 题目数 | 最近更新 | 文件 |
|------|------|--------|----------|------|
| Java | 集合 | 12 | YYYY-MM-DD | [集合](java/集合.md) |
```

题目数和更新时间必须与专题文件一致。没有根索引时创建；已有等价索引时沿用，不重复建立。

## 专题文件格式

```markdown
# {专题名称}

> 说明：{覆盖范围}
> 最近更新：YYYY-MM-DD

---

## {真实、可直接提问的问题标题}

<a id="{stable-id}"></a>

> ID：`{stable-id}`
> 标签：`{tag-1}`、`{tag-2}`
> 难度：基础 | 进阶 | 场景
> 最近校验：YYYY-MM-DD
> 适用范围：{JDK/框架/协议版本或“通用”}

### 简答

{先直接回答问题，内容适合 30～90 秒口述。}

### 原理展开

{解释必要术语、机制、执行链和因果关系。按内容选择段落、列表、表格或代码。}

### 常见追问

- {追问一}
- {追问二}

### 易错点与边界

- {容易混淆的概念、例外、版本差异或实际工程边界}

### 来源

- [{资料标题}]({URL}) — {官方/规范/源码/面试题库/二手资料}，访问于 YYYY-MM-DD
- 对话来源：{当前对话或可定位的任务标题/日期；没有稳定链接时不伪造链接}

---
```

简单问题可以省略“原理展开”或“常见追问”，但不得省略直接答案和来源。没有可靠外部来源时，明确写“待外部校验”，不能伪造引用。

不在每个问题正文中维护修订记录。修订时直接更新答案，“最近校验”反映当前内容的最后校验日期；纠错或版本调整的依据归入“来源”或“易错点与边界”，历史变更由 Git 追踪。

## 稳定 ID

格式建议：

```text
{domain}-{topic}-{question-slug}
```

示例：

- `java-collection-hashmap-thread-safety`
- `java-jvm-class-loading-parent-delegation`
- `database-mysql-leftmost-prefix`

规则：

- 使用小写英文、数字和连字符
- 同一问题合并或迁移时保留 ID
- 问法调整不应随意更换 ID
- 拆成两个独立问题时保留主问题 ID，并为新问题创建新 ID

## 归一化与去重

比较顺序：

1. 问题意图是否相同
2. 核心对象和机制是否相同
3. 适用版本和场景是否相同
4. 已有答案是否覆盖本次新增信息
5. 来源可靠性是否更高或更新

仅关键词重合不能证明重复；标题不同也不能证明是新题。

常见处理：

- 同义问法：保留一个主标题，其他问法写入标题下的别名说明或索引关键词
- 父子问题：主问题保留概览，独立且高频的子问题单列，并互相链接
- 版本差异：同一条目分版本说明，不重复创建近似标题
- 错误旧答案：更新正文，将纠错依据写入来源或易错点与边界，历史交由 Git 追踪
- 来源新增但内容无新增：只在来源能提升可信度时补充，否则跳过
- 大专题失控：按稳定知识域拆文件，同时修复根索引和内部链接

## 覆盖矩阵

```markdown
| 候选问题 | 来源 | 已有匹配 | 决策 | 目标文件/ID | 理由 |
|----------|------|----------|------|---------------|------|
| ... | JavaGuide | java-... | 合并 | java/集合.md | 补充 JDK 8 实现边界 |
```

每个候选必须有处理结果，不得只展示最终新增项。

## 质量检查

- [ ] 标题像真实面试问题，而不是宽泛名词
- [ ] 简答先给结论，能够直接口述
- [ ] 原理解释没有跳过关键主语、前提和因果
- [ ] 事实、经验和推断已区分
- [ ] 版本敏感内容注明适用范围
- [ ] 至少有一个可追溯来源，或明确标记待校验
- [ ] 没有与已有条目重复
- [ ] 稳定 ID、索引、内部链接有效
- [ ] 修订没有无意删除仍有效的内容
- [ ] 没有大段复制网站原文
