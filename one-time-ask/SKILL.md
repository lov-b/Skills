# One-Time Ask — 不打断任务的对话内确认

启用本 skill 后，**凡需用户回答、选择、确认**，一律通过 **AskQuestion** 在**当前任务流**内完成；用户在弹框中选择/回答，Agent **在同一轮继续执行**，不因「等你下一条消息」而中断任务。

## 触发条件

- 用户消息以 **`/one-time-ask`** 开头
- 用户显式选中或 @ 本 skill

可与其它 skill（如 `bugfix`、`manage-skills`）**叠加**：本 skill 约束**交互方式**，不替代具体业务流程。

---

## 核心原则

1. **禁止中断式追问**：不得在有未完成步骤时结束回复，仅留下「请告诉我…」「你选择哪个？」等**等待下轮消息**的纯追问
2. **一律 AskQuestion**：信息缺失、方案选择、是否继续、权限相关确认 → **AskQuestion** 弹框
3. **同轮续跑**：收到 AskQuestion 结果后**立即**继续当前 workflow，不插入「收到，下一轮再…」
4. **弹框即授权**：用户在该对话框中的选择视为对本步的确认；Agent 按选择执行后续工具调用

---

## 适用场景

| 场景 | 做法 |
|------|------|
| Bug 信息不全 | AskQuestion 补现象/复现/期望 |
| 多方案抉择 | AskQuestion 列选项 + 利弊摘要 |
| 是否执行修复/落库 | AskQuestion 确认（可含「全选」） |
| 环境/数据风险操作 | AskQuestion 确认后再 Shell |
| 任务途中插入无关请求 | 见下方「上下文切换」 |

---

## 工作流程

### Step 1: 识别阻塞点

执行中遇「缺信息 / 需决策 / 需确认」→ 标记为阻塞点，**暂停该分支**，不猜测、不擅自默认。

### Step 2: 构造 AskQuestion

- `prompt`：一句话说明**当前进度** + **需要用户决定什么**
- `options`：2～5 个可执行项；需要多选时 `allow_multiple: true`
- 复杂场景提供 **「全选」** 或 **「取消/跳过」**（按场景）
- **禁止**空选项或仅「是/否」且无上下文

### Step 3: 同轮继续

根据用户选择：

- **继续原任务** → 从阻塞点接着执行
- **取消/跳过** → 说明影响，结束或降级该分支
- **切换话题** → 见 Step 4

**输出**：选择结果 + 下一步动作（一句话）。

### Step 4: 上下文切换（无关任务）

用户弹框选择或消息内容与**当前任务明显无关**时：

1. **判定**：新任务是独立请求，还是对当前任务的补充？
2. **独立请求**：简要记录当前任务 checkpoint（阶段 + 待决项），处理新任务；完成后 AskQuestion 是否**回到原任务**
3. **补充信息**：并入当前任务上下文，不重置进度

---

## 禁止与允许

**禁止：**

- 以自然语言结尾「请回复我 X」并**结束 turn**（无 AskQuestion）
- 拆成多轮「只问不修 / 只问不做」的纯聊天
- 忽略 AskQuestion 结果，重复询问同一决策

**允许：**

- 复杂 Bug **多轮对话**，但每轮内需决策处仍用 AskQuestion；轮间保留 checklist
- 用户明确「不用问我，直接做」→ 跳过非关键 AskQuestion，关键风险确认仍保留

---

## 与其它 Skill 的关系

- **bugfix**：修复确认、归档、环境刷新等关口 → 本 skill 要求用 AskQuestion，同轮或下轮接续执行
- **manage-skills**：落库确认 → 本 skill 已对齐（单次 AskQuestion + 同轮落库）

---

## 注意事项

- **AskQuestion 不可用时**：若无法呼起 AskQuestion，**必须在对话中提示**：当前模型无法呼出 AskQuestion，需要纯文本确认；再一次性列清所需信息的最小集合，用编号选项请用户回复——仅作降级，非首选
- 选项文案具体可执行，避免「好的」「继续」等模糊项
- 每次 AskQuestion 前用 1～2 句说明**已完成什么**，避免用户丢失上下文
